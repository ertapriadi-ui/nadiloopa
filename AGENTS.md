# NADILOOPA — Agent & Cloud Collaboration Guide (`AGENTS.md`)

Welcome, cloud agent! This repository holds the full Godot `4.7.2-stable` source project for **NADILOOPA** (`v2.2.0`, `package: com.nadiloopa.puzzle`), a portrait (`1080×2400`) Android puzzle game featuring 7 smiling 3D organ mascots, dynamic difficulty grid sizes, Nadi Loop combos, angry saturated-fat food hazards, and colorful veggie/fruit bonuses.

## 1. Repository Architecture
- `project.godot` / `export_presets.cfg`: Godot `4.7.2` (`gl_compatibility`, portrait orientation, Android package `com.nadiloopa.puzzle`, `version/code=4`, `version/name="2.2.0"`).
- `scripts/autoload/`:
  - `game_manager.gd`: Play states (`MENU`, `READY`, `SELECTING`, `RESOLVING`, `WIN`, `LOSE`, `PAUSED`) and balance config loader (`data/game_config.json`).
  - `save_manager.gd`: Schema v2 local persistence (`unlocked_level`, stars, high scores, daily streak, achievements, settings including `"difficulty"` for grid sizing, SHA-256 checksum & `.bak` corrupt recovery).
  - `localization_manager.gd`: Bilingual EN/ID loader (`data/translations/strings_en_id.json`) + `validate_parity()`.
  - `audio_manager.gd`: 4 procedural BGM tracks + 21 SFX events.
- `scripts/core/`:
  - `board_state.gd`: `ORGANS = ["heart", "brain", "lungs", "kidneys", "stomach", "liver", "muscle"]` (where `"liver"` key holds **Pancreas**). Adaptive grid dimensions set via `BoardState.set_difficulty_grid(diff)`:
    - `"easy"` -> `5×7` (`35` cells)
    - `"medium"` -> `6×9` (`54` cells)
    - `"hard"` -> `7×12` (`84` cells)
  - `chain_validator.gd`: Orthogonal drag chaining (`min_len = 3`), backtracking, and closed `Nadi Loop` circuit detection (`>= 5` steps closing onto an earlier tile).
  - `chain_resolver.gd`: Turn resolution, combo streaks, `healthy_popped` side-chain pops (`care` Salad +120 pts / +10 Energy / +5 Pulse; `bloom` Antioxidant Fruit +180 pts / +10 Energy / +5 Pulse), 4-way/8-way Endpoint Pulse (`PulseSystem`), restrictions expiry, gravity/refill, and win/lose checks.
  - `booster_system.gd`, `hazard_system.gd`, `pulse_system.gd`, `level_manager.gd`, `score_manager.gd`.
- `scripts/ui/`:
  - `main_controller.gd`: Minimalist large-font UI, Easy/Medium/Hard difficulty selector, 100-stage Campaign + Endless Zen + Daily Sanctuary, Settings & Bilingual Almanac, plus the 7 dancing organ mascots parade in `_modal_win`.
  - `board_renderer.gd`: Adaptive cell geometry, `95%` square-filling glossy mascot tiles, `start_victory_dance()` happy jump/sway animation on win, preview badges, and idle hand hints.
  - `touch_input_controller.gd` & `vfx_controller.gd`.
- `data/`:
  - `levels/levels_v1.json`: 100 deterministic stages generated by `tools/generate_100_levels.py`.
  - `translations/strings_en_id.json`: Full English & Indonesian string table.
- `tools/`:
  - `build_all_3d_assets.ps1`: Windows .NET sprite compositor (`icon_1024.png`, `organ_*.png`, `special_*.png`).
  - `generate_100_levels.py`: Deterministic level generator.
  - `capture_screenshots.gd`: Headless/windowed SubViewport screenshot verifier across `720x1600`, `1080x1920`, `1080x2400`, `1440x3200`.

## 2. Mandatory Multi-Stream Git Workflow (Kerja Bersama)
To coordinate work cleanly across multiple agents without merge conflicts:
1. Always sync `main` first (`git fetch origin && git pull --rebase origin main`).
2. Never commit directly to `main` when multiple streams run simultaneously — create a stream branch:
   - `stream/gameplay-<task>` (`scripts/core/`, `data/levels/`, `tests/`)
   - `stream/ui-visuals-<task>` (`scripts/ui/`, `assets/`, `scenes/`)
   - `stream/cloud-backend-<task>` (`scripts/autoload/save_manager.gd`, `tools/`, `.github/`)
   - `stream/qa-release-<task>` (`tests/`, `QA_REPORT.md`, `export_presets.cfg`)
3. Touch only files owned by your stream whenever possible. Before pushing your branch or opening a Pull Request, run the full QA gate below and confirm **0 failures**.

## 3. Mandatory Verification Gate (Headless Linux / Windows)
```bash
# 1. Refresh Godot asset imports
godot --headless --path . --import --quit

# 2. Run automated QA + 100-level solvability simulator (must exit 0, 0 failed)
godot --headless --path . -s res://tests/test_suite.gd
```

## 4. Versioning & Release Rules
- Every PR merged to `main` that changes gameplay, assets, UI, or levels should ensure `tests/test_suite.gd` passes (`447+ assertions, 0 failed`).
- If bumping app version, update both `export_presets.cfg` (`version/code`, `version/name`) and `project.godot` (`config/version`) together.
